# Decisions

Choices that look like accidents without their context. Each one says what was decided, why, and when to look at it
again. Newest first.

## Per-request CSP nonce for inline scripts (2026/10/04)

- **Context:** the CSP allowed `'unsafe-inline'` scripts. Besides our own inline scripts (gtag, theme), Angular SSR adds
  inline scripts of its own (event replay, critical CSS), so a static hash list isn't practical.
- **Decision:** the server generates a nonce per response (`middleware/csp-nonce.ts`). `index.html` marks it with
  `ngCspNonce="CSP_NONCE_PLACEHOLDER"`, which Angular copies onto every inline script, and `applyCspNonce` swaps in the
  real nonce for rendered and cached pages alike. Inline event handlers are blocked (`script-src-attr 'none'`).
- **Revisit:** when adding a new path that serves HTML: it must call `applyCspNonce`, or its scripts won't run.

## Every replica pre-renders its own pages (2026/10/04)

- **Context:** the auto-generator in each pod renders and refreshes the pages in `serverConfig.autoGeneratedPages` on
  its own timers. With 2 replicas that doubles the upstream calls for those pages, and the pods can serve slightly
  different versions of `/` for up to 5 minutes.
- **Decision:** accept it. At 2 replicas and a handful of pages the cost is negligible, and a shared cache would add a
  moving part (Redis or similar) to the cluster.
- **Revisit:** above 2 replicas, or if the list of auto-generated pages grows a lot.

## Production-only configuration (2026/10/04)

- **Context:** `src/config/config.ts` points at the production API, hiscores proxy and wiki prices, with no development
  or staging variant. The API's CORS only allows `http://localhost:4200`, so local runs must use that port.
- **Decision:** stay production-only. A separate development environment (local API stack, build-time file replacement)
  is overkill for a single-maintainer hobby project that only reads public data.
- **Revisit:** if local work ever needs to write data, or a change has to be tested against an unreleased API.

## Changelog is for users, plus one maintenance bullet (2026/10/04)

- **Context:** `CHANGELOG.md` is rendered on `/about/changelog`, but every change (dependencies, tooling, server
  hardening) gets an entry.
- **Decision:** write bullets for users. Changes users can't see go in a "Behind-the-scenes maintenance: …" bullet.
- **Revisit:** if the changelog page gets noisy, merge a day's maintenance bullets into one.
